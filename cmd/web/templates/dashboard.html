Fake supplier

The supplier sends the feed's batch files one by one. initial: 3 batches, 10 new products. changes: 3 batches with updates, withdrawals, duplicates, out-of-order and invalid records. Settings return to these defaults when the server restarts.

Try it

  1. First update. Supplier feed initial, no outage. Press Start update: completed, 10 products created.
  2. The supplier goes down mid-update. Feed changes, outage at batch 3, Save, Start update. After about 15 s of retries the update is failed and NOT FINISHED: batches 1–2 stay applied, nothing is lost. Start update again is refused.
  3. The supplier is back. Outage none, Save, press Resume: only batch 3 is fetched, then completed_with_problems. Open the update to see each change (old → new), stale and duplicate records skipped, and Problems for the invalid records.
  4. Import the same data again. Start update: 0 changes, no duplicate products. The status is still completed_with_problems because the feed's invalid records are reported again.
  5. The application crashes. Feed initial, then Start update with crash after batch 1. The server process really exits; the host restarts it (a few seconds, up to a minute on a free plan). Reload: the update shows interrupted. Press Resume to finish it.

The same scenarios run from the command line, see the README.
